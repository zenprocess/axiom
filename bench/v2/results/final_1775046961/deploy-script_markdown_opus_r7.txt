It looks like file write permissions aren't granted. Here's the script — you can save it as `deploy.sh` in your project root:

**Key design decisions:**

- **Version auto-detected** from `pyproject.toml` (currently `0.6.0`), or pass explicitly
- **No hardcoded secrets** — registry, host, and user come from env vars
- **Automatic rollback** — if the health check fails after deploy, the previous container is restored immediately
- **Manual rollback** — `./deploy.sh rollback 0.5.0` pulls and deploys any previously pushed version
- **Confirmation prompt** before any production-affecting action
- **Blue-green style** — the old container is renamed to `*-prev` and only removed after the new one passes health checks

**Usage:**

```bash
# Deploy current version from pyproject.toml
DOCKER_REGISTRY=ghcr.io/zenprocess DEPLOY_HOST=prod.example.com DEPLOY_USER=deploy \
  ./deploy.sh deploy

# Deploy a specific version
./deploy.sh deploy 0.7.0

# Roll back to a previous version
./deploy.sh rollback 0.5.0
```

**The 4 stages:**

1. **Build** — `docker build` with version + git SHA labels, tags both `:{version}` and `:latest`
2. **Push** — pushes both tags to `$DOCKER_REGISTRY`
3. **Git tag** — creates annotated tag `v{version}` and pushes to origin (idempotent if tag exists)
4. **Deploy** — SSHs to production, pulls image, stops old container (renamed for rollback), starts new one, runs health check on `:8000/health` with configurable timeout

**Rollback flow:**

- **Automatic**: if the health check fails during deploy, the previous container (`*-prev`) is swapped back in
- **Manual**: `rollback VERSION` verifies the image exists in the registry, then pulls and deploys it with the same health check

You'll need to adjust the port (`8000`), health endpoint (`/health`), and env-file path (`/etc/axiom-rdl/.env`) to match your actual setup. You'll also need a `Dockerfile` in the project root.
