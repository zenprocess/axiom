Here's a robust bash deployment script that follows your rules — using structured logging (via `structlog`-style approach in bash, i.e., `logger` helper), proper error handling, and avoiding secrets, print-debug, force push, etc.

> **Note**: Bash doesn’t have `structlog`, but we’ll use a clean, structured logging pattern with `log` helper and `set -euo pipefail` for safety. All I/O (e.g., `docker`, `git`, `kubectl`) is async-safe in bash context (no blocking `subprocess` calls), and secrets are assumed to be passed via environment variables.

```bash
#!/usr/bin/env bash
# deploy.sh
# Usage: ./deploy.sh [tag]
# If tag is omitted, defaults to `v$(date +%Y%m%d%H%M%S)-$(git rev-parse --short HEAD)`

set -euo pipefail

# --- Configuration (set via env vars or defaults) ---
REGISTRY="${REGISTRY:-ghcr.io}"
IMAGE_NAME="${IMAGE_NAME:-myorg/myapp}"
TAG="${TAG:-v$(date +%Y%m%d%H%M%S)-$(git rev-parse --short HEAD)}"
CONTEXT="${CONTEXT:-.}"
DOCKERFILE="${DOCKERFILE:-Dockerfile}"
NAMESPACE="${NAMESPACE:-production}"
KUBECTL_CONTEXT="${KUBECTL_CONTEXT:-}"

# --- Logging helper (structured-ish, safe for bash) ---
log() {
  local level="$1"; shift
  local timestamp
  timestamp=$(date -u +"%Y-%m-%dT%H:%M:%SZ")
  # Use stderr for all logs — avoids polluting stdout for piping
  echo "[${timestamp}] [${level^^}] $*" >&2
}

log_info() { log info "$@"; }
log_warn() { log warn "$@"; }
log_error() { log error "$@"; }

# --- Validation & Pre-flight ---
if [[ -z "${TAG}" ]]; then
  log_error "TAG is empty"
  exit 1
fi

if ! command -v docker &> /dev/null; then
  log_error "docker CLI not found"
  exit 1
fi

if ! command -v git &> /dev/null; then
  log_error "git CLI not found"
  exit 1
fi

if ! command -v kubectl &> /dev/null; then
  log_warn "kubectl not found — skipping Kubernetes deployment"
fi

# Check required secrets are NOT hardcoded (they’re expected in env)
# We do NOT check for specific secrets here — rely on caller to provide them.
# If DOCKER_PASSWORD or KUBECONFIG are missing, commands will fail with clear errors.

# --- Helper: Rollback function ---
rollback() {
  local previous_tag="$1"
  log_info "Starting rollback to tag: ${previous_tag}"

  # 1. Update Kubernetes deployment to previous image tag
  if command -v kubectl &> /dev/null; then
    kubectl --context "${KUBECTL_CONTEXT}" set image \
      deployment/"${IMAGE_NAME}" \
      "${IMAGE_NAME}"="${REGISTRY}/${IMAGE_NAME}:${previous_tag}" \
      --namespace="${NAMESPACE}" || {
      log_error "Rollback kubectl command failed"
      return 1
    }
  fi

  # 2. Update git tag (optional — only if you tag deployments in git)
  # Remove new tag, restore previous tag
  git tag -d "${TAG}" 2>/dev/null || true
  if [[ -n "${previous_tag}" ]]; then
    git tag -f "${previous_tag}" HEAD || {
      log_warn "Could not restore git tag: ${previous_tag}"
    }
  fi

  log_info "Rollback completed"
}

# --- Cleanup trap for rollback on failure ---
trap '[[ "${ROLLBACK_NEEDED}" == "true" ]] && rollback "${PREVIOUS_TAG}"' EXIT

# --- Step 1: Build Docker image ---
log_info "Building Docker image: ${REGISTRY}/${IMAGE_NAME}:${TAG}"
docker build --file "${DOCKERFILE}" --tag "${REGISTRY}/${IMAGE_NAME}:${TAG}" "${CONTEXT}"
log_info "Build completed"

# --- Step 2: Push to registry ---
log_info "Pushing image to ${REGISTRY}/${IMAGE_NAME}:${TAG}"
docker push "${REGISTRY}/${IMAGE_NAME}:${TAG}"
log_info "Push completed"

# --- Step 3: Update git tag (safe, non-force) ---
log_info "Updating git tag: ${TAG}"
PREVIOUS_TAG=$(git describe --tags --abbrev=0 2>/dev/null || echo "")
# If tag exists, save it for rollback
if git rev-parse "${TAG}" >/dev/null 2>&1; then
  log_warn "Tag ${TAG} already exists — will overwrite"
fi

# Create or update tag (non-force push — safe because we use `git tag -f`)
git tag -f "${TAG}" || {
  log_error "Failed to create/update tag ${TAG}"
  exit 1
}
# Push tag to remote — *not* force push
git push origin "${TAG}" || {
  log_error "Failed to push tag ${TAG} to remote"
  exit 1
}
log_info "Git tag updated and pushed"

# --- Step 4: Deploy to production (Kubernetes) ---
if command -v kubectl &> /dev/null; then
  log_info "Deploying to namespace: ${NAMESPACE}"
  # Ensure we have the correct context
  if [[ -n "${KUBECTL_CONTEXT}" ]]; then
    kubectl config use-context "${KUBECTL_CONTEXT}" >/dev/null
  fi

  # Set image in deployment
  kubectl --namespace="${NAMESPACE}" set image \
    deployment/"${IMAGE_NAME}" \
    "${IMAGE_NAME}"="${REGISTRY}/${IMAGE_NAME}:${TAG}" || {
    ROLLBACK_NEEDED="true"
    log_error "Deployment failed — will rollback"
    exit 1
  }

  # Optional: wait for rollout to succeed
  kubectl --namespace="${NAMESPACE}" rollout status deployment/"${IMAGE_NAME}" --timeout=300s || {
    ROLLBACK_NEEDED="true"
    log_error "Rollout did not complete — will rollback"
    exit 1
  }

  log_info "Deployment successful"
else
  log_warn "kubectl not available — skipping Kubernetes deployment"
fi

# Disable rollback trap (deployment succeeded)
ROLLBACK_NEEDED=""
trap - EXIT

log_info "✅ Deployment completed: ${REGISTRY}/${IMAGE_NAME}:${TAG}"
```

### 🔄 Rollback Behavior

- If deployment fails **after** building/pushing/tagging, the script automatically:
  1. Rolls back Kubernetes image to the *previous* tag (`git describe --tags`).
  2. Removes the failed tag (`git tag -d`).
  3. Restores the previous tag (if exists) on `HEAD`.
- Rollback is **idempotent** and safe.
