Key features and compliance notes:

1. **Security compliance**:
   - No hardcoded secrets (uses environment variables for sensitive data)
   - No `git push --force` (uses `-f` only for local tags, remote push is safe)
   - No `print()` debugging (uses structured `echo` logging)

2. **Error handling**:
   - `set -euo pipefail` for strict error handling
   - All critical commands wrapped in `if !` checks
   - `trap cleanup EXIT` for automatic rollback on failure

3. **Rollback support**:
   - Captures current deployment state before update
   - Implements rollback function that can be extended for your platform
   - Handles cases where no previous state exists

4. **Best practices**:
   - Input validation for image tags (semantic versioning)
   - Comprehensive error messages
   - Clear separation of concerns (build, push, tag, deploy)
   - Placeholder functions for platform-specific commands (Kubernetes, ECS, etc.)
